# System account password recovery

Active system accounts can recover their password from the web or mobile login screen using a phone number registered to the account, its linked household, or its linked responder record.

The recovery flow uses these unauthenticated, rate-limited API routes:

- `POST /api/v1/auth/password-recovery/household/lookup` — resolves a system account ID and returns only a masked phone number.
- `POST /api/v1/auth/password-recovery/household/validate-contact` — compares the entered number with a phone number registered to that account.
- `POST /api/v1/auth/password-recovery/household/send-code` — sends a six-digit, ten-minute OTP by push to an active, previously registered Android/iOS app device; if no eligible device accepts the notification, it falls back to the configured Android SMS Gateway and then Semaphore.
- `POST /api/v1/auth/password-recovery/household/reset` — verifies the OTP, changes the password, and revokes existing sessions.

Run the `2026_10_25_000001_create_household_password_recovery_otps` migration before enabling the flow.

For a no-SMS-aggregator-account setup, install **SMS Gateway for Android** on the Android phone with the active SIM and use its **Cloud Server** mode. This works when the backend is not on the phone's Wi-Fi:

```dotenv
SMS_GATEWAY_BASE_URL=https://api.sms-gate.app/3rdparty/v1
SMS_GATEWAY_USERNAME=<username-shown-in-the-app>
SMS_GATEWAY_PASSWORD=<password-shown-in-the-app>
SMS_GATEWAY_MESSAGE_PATH=/messages
```

In the Android app, enable **Cloud Server**, tap **Offline** to connect, and wait until it shows **Online**. The app generates the username/password shown in its Cloud Server section; use those as backend-only credentials. Keep the app/device online and allowed to send SMS. The cloud server mode requires no SMS aggregator account/API key; carrier charges or plan limits may still apply. Restart/reload Laravel's cached configuration after changing backend environment values.

Alternatively, **Local Server** mode requires the backend and phone to share a reachable LAN: use the local URL and Basic Authentication credentials shown in the app, with `SMS_GATEWAY_MESSAGE_PATH=/message`. Do not expose the Local Server to the public internet.

For internet-only delivery, configure OneSignal (`ONESIGNAL_APP_ID` and `ONESIGNAL_API_KEY`) and ensure the account has an active app device registered with push notifications enabled. The OTP push is sent only to active Android/iOS subscriptions associated with that account. The code appears in the notification, so users should protect access to their device and lock-screen notification previews. Devices without an eligible push subscription, or requests not accepted by OneSignal, fall back to SMS.

The OTP is generated by the backend and stored only as a password hash after a provider accepts the send. The code expires after ten minutes, permits at most five incorrect attempts, and is invalidated after successful use. A user can request up to three codes per minute. The mobile and web buttons disable while a request is being sent and start a visible one-minute cooldown after the third request. Additional requests during the server-side cooldown return an informational response with a countdown rather than a “Too Many Attempts” error. SMS provider configuration or delivery failures remain visible so they can be corrected. Push delivery requires internet connectivity and an enrolled app device; SMS fallback may incur carrier or provider charges. The mobile OTP field supports platform one-time-code suggestions where available.


If sign-in reports that the account password cannot be verified, use **Forgot
password** to set a new password. This can happen when an old account has a
stored password value that is not a supported Laravel password hash; the API
will not treat that value as a valid password or return a server error.
